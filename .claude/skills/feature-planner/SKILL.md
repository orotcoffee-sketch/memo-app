# feature-planner

기능 하나를 기획부터 이슈 등록까지 진행한다. 인자(`$ARGUMENTS`)가 기능 이름이다. 없으면 먼저 묻는다.

모든 문서는 `docs/features/<기능>/` 에 둔다 (예: `docs/features/tag/prd.md`).

## 규칙

- **[멈춤]** 표시가 있는 곳에서는 **반드시 사람에게 묻고 답을 기다린다.** 답이 없으면 다음 단계로 가지 않는다. 내가 대신 고르거나 "진행하겠습니다" 하고 넘어가지 않는다.
- 질문은 **한 번에 하나씩** 한다. 여러 질문을 묶어서 던지지 않는다.
- 이 스킬은 문서와 이슈만 만든다. `src/` 코드는 건드리지 않는다.
- 커밋은 하지 않는다. 사용자가 요청할 때만 한다.

## 절차

### 1. 스펙 확정 (인터뷰)

1. `docs/features/<기능>/spec-original.md` 를 읽는다. 없으면 멈추고 사용자에게 알린다.
2. 모호하거나 빠진 부분, 서로 부딪히는 부분을 찾아 질문 목록을 속으로 만든다. 코드로 답을 알 수 있는 것은 묻지 말고 `src/` 에서 확인한다.
3. **한 번에 질문 하나**를 한다. 매 질문에 **추천 답과 그 이유**를 함께 적는다. (예: "추천: 대소문자 구분 안 함 — 사용자가 `#Work` 와 `#work` 를 다른 태그로 의도하는 경우가 드물기 때문")
4. 답을 받으면 다음 질문으로 간다. 모든 질문이 끝나면 확정된 내용을 `spec-fixed.md` 에 쓴다 (원본의 결정 사항 + 인터뷰로 정한 항목, 각 항목에 근거).

### 2. PRD 작성

`docs/features/<기능>/prd.md` 를 아래 5개 섹션으로 쓴다. 근거 문서(`spec-fixed.md`) 링크를 맨 위에 둔다.

1. **개요** — 기능이 무엇이고 왜 필요한지 2~3문장.
2. **사용자 이야기** — "~로서, ~할 수 있다" 형식으로 한 줄씩.
3. **기술 결정** — 아래 절차를 따른다.
4. **이번에 안 만들 것** — 범위 밖 항목 목록.
5. **용어 정의** — 문서에서 쓰는 용어와 뜻.

#### 기술 결정 절차

1. 해결해야 할 기술 문제마다 **3가지 안**을 **표로 비교**한다. 기준(데이터 구조, 고칠 곳, 기존 코드와 비슷한 정도, 테스트 쉬움, 복잡도 등)을 행으로, 안을 열로 둔다. 어느 안이 낫다고 추천 의견을 달 수는 있지만 확정하지 않는다.
2. **[멈춤]** 표를 보여 주고 **사람이 안을 고를 때까지 기다린다.**
3. 고른 뒤에 아래 **4가지로 기록**한다.
   - **상황** — 왜 결정이 필요한가 (현재 구조와 제약)
   - **대안** — 비교한 3안 (표)
   - **결정** — 고른 안과 구체적인 규칙
   - **결과** — 장점과 단점(감수할 것)

### 3. "안 만들 것" 확인

**[멈춤]** `prd.md` 의 "이번에 안 만들 것" 목록을 사용자에게 **그대로 보여 주고 확인**받는다. 빠진 것, 빼야 할 것이 있으면 고친 뒤 다시 확인받는다. 확인 전에는 4단계로 가지 않는다.

### 4. 이슈 분해

- 이슈 **하나만 끝내도 사용자가 화면에서 볼 수 있도록** 세로로(기능 단위로) 쪼갠다. "파싱 함수 만들기" 처럼 눈에 안 보이는 내부 작업 단위로 쪼개지 않는다.
- 각 이슈는 제목, 한 줄 설명, **완료 체크리스트**로 구성한다. 체크리스트는 **"~일 때 / ~하면 / ~된다"** 형식으로, 눈으로 확인할 수 있는 문장이어야 한다.
  - 예: `- [ ] 메모에 #업무가 있으면 메모 아래에 #업무 칩이 보인다`
- 이슈 간 순서(먼저 끝나야 하는 것)가 있으면 표시한다.
- "이번에 안 만들 것" 에 있는 내용이 이슈에 들어가지 않았는지 확인한다.

### 5. 이슈 등록

1. **[멈춤]** 이슈 목록(제목 + 체크리스트 전체)을 사용자에게 보여 주고 **확인받는다.** 수정 요청이 있으면 고치고 다시 확인받는다.
2. 승인되면 `gh issue create --title "..." --body "..."` 로 하나씩 등록한다. 본문은 설명과 체크리스트다.
3. 등록한 이슈 번호와 주소를 표로 보고한다.

## 마무리 보고

만든 문서(`spec-fixed.md`, `prd.md`) 경로와 등록한 이슈 목록을 알리고, 다음 단계로 `/test-scenarios <이슈번호>` 를 안내한다.
