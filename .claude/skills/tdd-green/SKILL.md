# tdd-green

TDD의 Green 단계다. 실패하는 테스트를 하나씩 통과시킨다. 인자(`$ARGUMENTS`)가 있으면 그 테스트 파일의 실패만 대상으로 하고, 없으면 전체 실패를 대상으로 한다.

## 규칙

- **YAGNI**: 테스트에 없는 기능, 분기, 옵션, 방어 코드를 추가하지 않는다.
- **테스트 파일은 수정하지 않는다.** 테스트가 틀렸다고 판단되면 고치지 말고 멈춰서 사용자에게 보고한다.
- 구현은 `src/` 의 구현 파일만 고친다. 코딩 규칙(CLAUDE.md)은 지킨다.

## 절차

1. **현재 상태 확인** — 감시 모드에 걸리지 않도록 `npm test -- --run` 을 실행해 실패 테스트 목록과 실패 이유를 본다. 실패가 0개면 "남은 실패: 0" 을 보고하고 끝낸다.

2. **하나만 고르기** — 실패한 테스트 **하나**를 고른다. 같은 파일에서는 위에서 아래 순서, 쉬운 것(단순 입력→출력)을 먼저 고른다.

3. **최소 구현** — 고른 테스트만 통과시키는 가장 작은 변경을 한다. 다음 테스트를 미리 대비한 일반화는 하지 않는다. 고치기 전에 바꿀 부분의 원래 내용을 기억해 둔다(되돌리기 위해).

4. **전체 실행** — 매번 `npm test -- --run` 으로 **전체** 테스트를 돌린다.
   - 고른 테스트가 통과하고 이전에 통과하던 테스트가 모두 그대로 통과 → 다음 테스트로 간다(2단계).
   - **이전에 통과하던 다른 테스트가 깨졌다** → 방금 변경을 **되돌리고**(3단계에서 기억한 원래 내용으로 직접 복원) 다른 방식으로 다시 시도한다. 이 되돌림에 `git reset --hard`, `git checkout --` 같은 명령은 쓰지 않는다. 커밋 안 된 다른 작업이 함께 사라질 수 있다.
   - 고른 테스트가 아직 실패 → 같은 테스트의 실패 횟수를 1 올리고 다시 시도한다.

5. **5번 실패하면 멈춤** — **같은 테스트**가 5번 연속 통과하지 못하면 더 시도하지 않고 멈춘다. 보고에 아래를 적는다.
   - 멈춘 테스트 이름
   - 시도한 접근 5가지와 각각의 실패 이유
   - 테스트나 설계에 문제가 있어 보이는지에 대한 판단

6. **반복** — 실패 수가 0이 될 때까지 2~4단계를 반복한다. 테스트 하나를 통과시킨 뒤에도 전체 실행으로 확인한다.

7. **마지막 보고** — 아래를 짧게 알리고, **맨 마지막 줄**에 남은 실패 수를 출력한다.
   - 통과시킨 테스트 목록과 바꾼 파일
   - 되돌린 시도가 있었다면 그 내용
   - 마지막 줄: `남은 실패: n`

   실패가 모두 해결되면 `남은 실패: 0`, 5번 실패로 멈췄으면 그때의 실제 실패 수를 쓴다.

## 주의

- 커밋은 하지 않는다. 사용자가 요청할 때만 한다.
- 끝나기 전에 `npx tsc -b` 와 `npm run lint` 도 실행해 타입·린트 오류가 없는지 확인한다.
- 리팩터링은 이 단계에서 하지 않는다. 필요하면 보고에 제안만 한다.
