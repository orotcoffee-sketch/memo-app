# tdd-refactor

TDD의 Refactor 단계다. **동작은 바꾸지 않고 구조만 개선한다.** 인자(`$ARGUMENTS`)가 있으면 그 파일/폴더만, 없으면 `src/` 전체를 대상으로 한다.

## 규칙

- **동작 불변**: 기능 추가, 버그 수정, 출력·UI 텍스트 변경을 하지 않는다. 필요해 보이면 고치지 말고 보고에 제안만 한다.
- **테스트 파일은 수정하지 않는다.** 테스트가 구조에 묶여 있어 깨지면 리팩터링 쪽을 되돌린다.
- **한 번에 하나만** 고친다. 여러 개선을 한꺼번에 하지 않는다.
- 시작할 때 테스트가 이미 실패 중이면 리팩터링하지 않고 멈춰서 보고한다.

## 점검 기준 (5개)

1. **중복** — 같거나 거의 같은 코드가 반복된다. 함수/상수/컴포넌트로 추출한다.
2. **이름** — 변수·함수·파일 이름이 역할을 드러내지 못한다. 의도가 드러나는 이름으로 바꾼다.
3. **한 함수가 너무 많은 일** — 한 함수가 여러 책임(검증+변환+저장 등)을 진다. 책임별로 나눈다.
4. **매직넘버** — 의미 없이 쓰인 숫자·문자열 리터럴(예: localStorage 키, 길이 제한). 이름 있는 상수로 바꾼다.
5. **CLAUDE.md 규칙 위반** — CLAUDE.md의 코딩 규칙을 확인한다: named export만 사용(`App` 제외), 이벤트 함수는 `handle` 로 시작, 파일명 규칙(컴포넌트 PascalCase / 그 외 camelCase), 테스트 파일 위치, 파일 200줄 이하, 컴포넌트는 storage·memo state를 직접 다루지 않음.

## 절차

1. **기준선 확인** — `npm test -- --run` 을 실행한다(감시 모드 방지). 전부 통과해야 시작한다. 통과 개수를 기록하고, 대상 파일의 줄 수 등 "전" 상태를 기억해 둔다.

2. **점검** — 대상 코드를 읽고 5개 기준별로 문제를 찾아 목록으로 만든다. 항목마다 파일·위치·기준·고칠 방법을 한 줄로 적는다. 문제가 없으면 "개선할 항목 없음"으로 보고하고 끝낸다.

3. **하나 고르기** — 목록에서 영향이 작고 안전한 것부터 **하나**만 고른다. 고치기 전에 바꿀 부분의 원래 내용을 기억해 둔다(되돌리기 위해).

4. **수정** — 그 하나만 고친다. 동작이 달라질 수 있는 변경은 하지 않는다.

5. **테스트** — `npm test -- --run` 으로 **전체** 테스트를 돌린다.
   - 기준선과 같이 모두 통과 → 해당 항목을 완료로 표시하고 3단계로 돌아간다.
   - **하나라도 깨졌다** → **즉시 되돌린다**(4단계에서 기억한 원래 내용으로 직접 복원). `git reset --hard`, `git checkout --` 같은 명령은 쓰지 않는다. 커밋 안 된 다른 작업이 사라질 수 있다. 되돌린 뒤 테스트가 다시 통과하는지 확인하고, 그 항목은 "건너뜀(사유)"로 표시한 뒤 다음 항목으로 넘어간다. 같은 항목을 다른 방식으로 재시도하는 것은 한 번까지만 한다.

6. **반복** — 목록이 빌 때까지 3~5단계를 반복한다.

7. **마무리 검증** — `npx tsc -b` 와 `npm run lint` 로 타입·린트 오류가 없는지 확인한다.

8. **전후 비교 요약** — 아래 형식으로 짧게 보고한다.

   | 항목 | 기준 | 전 | 후 |
   |---|---|---|---|
   | 예: `App.tsx` | 매직넘버 | `'memos'` 리터럴 2곳 | `STORAGE_KEY` 상수 |

   - 완료한 개선 / 되돌려서 건너뛴 항목(사유) / 보고만 하는 제안
   - 바꾼 파일 목록, 테스트 통과 개수(전 → 후), 파일 줄 수 변화
   - 마지막 줄: `테스트: n개 통과 (전: n개)`

## 주의

- 커밋은 하지 않는다. 사용자가 요청할 때만 한다(형식: `refactor(범위): 설명`).
- 새 파일을 만들 때도 CLAUDE.md 규칙(named export, 파일명, 200줄)을 지킨다.
- 요청받지 않은 라이브러리 추가나 폴더 구조 대개편은 하지 않는다.
