# test-scenarios

이슈 번호 `$ARGUMENTS` 의 완료 체크리스트를 테스트 시나리오로 바꾼다. **구현 코드와 테스트 코드는 작성하지 않는다.** 산출물은 시나리오 문서뿐이다.

인자가 없거나 숫자가 아니면 이슈 번호를 사용자에게 묻고 멈춘다.

## 절차

1. **이슈 읽기** — `gh issue view $ARGUMENTS` 로 제목, 본문, 완료 체크리스트를 읽는다. Windows에서 `gh`를 못 찾으면 PowerShell에서 PATH를 새로 읽은 뒤 실행한다. 체크리스트 항목에는 순서대로 번호(C1, C2, …)를 붙인다.

2. **함수 시그니처 제안 → 승인** — 이슈를 만족시키는 데 필요한 함수마다 아래를 표로 제안한다. 이미 있는 함수(예: `src/utils/` 의 파일)는 기존 시그니처를 먼저 확인해 재사용을 우선한다.
   - 함수명, 파일 위치
   - 입력(이름: 타입)
   - 출력(타입)
   - 에러 시 동작과 에러 메시지(던지는지, 빈 값을 돌려주는지 포함)

   제안 후 **사용자 승인을 받을 때까지 다음 단계로 가지 않는다.** 수정 요청이 있으면 반영해 다시 제안한다.

3. **시나리오 제안** — 승인된 시그니처 기준으로 `[정상]`, `[경계]`, `[예외]` 로 나눠 제안한다.
   - 형식: `함수명 should ... when ...` (예: `parseTags should return an empty array when the text has no #`)
   - `[경계]` 에는 입력에 최댓값 개념이 있으면 **최대 − 1, 최대, 최대 + 1** 을 반드시 포함한다. 최댓값이 정해져 있지 않으면 그 사실을 적고, 사용자에게 최댓값을 정할지 묻는다.
   - 각 시나리오가 어느 체크리스트 항목(C번호)을 검증하는지 끝에 표시한다.

4. **대조표 → 승인** — 체크리스트 항목(C번호)과 시나리오를 짝지은 대조표를 보여 준다. 시나리오가 하나도 없는 항목이 있으면 표시하고 시나리오를 보강한다. 모든 항목이 채워진 뒤 **사용자 승인을 받는다.**

5. **저장** — 승인된 내용을 `docs/features/tag/scenarios-$ARGUMENTS.md` 에 쓴다. 구성은 아래 순서를 따른다.
   1. 이슈 번호와 제목
   2. 함수 시그니처 표
   3. `[정상]` / `[경계]` / `[예외]` 시나리오 목록
   4. 체크리스트 대조표

   저장 후 파일 경로와 시나리오 개수를 한 줄로 알린다.

## 주의

- 2단계와 4단계의 승인은 건너뛰지 않는다. 승인 전에는 파일을 쓰지 않는다.
- `src/` 는 수정하지 않는다.
- 이슈에 체크리스트가 없으면 본문에서 요구사항을 뽑아 제안하되, 그 사실을 사용자에게 알린다.
