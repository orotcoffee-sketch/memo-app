# 메모 인라인 수정 기능 PRD

근거 문서: [spec-fixed.md](./spec-fixed.md)

## 개요

목록에 있는 메모의 텍스트를 더블클릭하면 그 자리에서 한 줄 입력창으로 바뀌어 내용을 바로 고칠 수 있게 한다. 메모를 지우고 다시 쓰지 않아도 오타나 내용을 고칠 수 있다. 수정해도 메모의 위치와 만든 시각(`createdAt`)은 그대로이고, 태그 칩은 수정한 본문에 맞춰 자동으로 바뀐다.

## 사용자 이야기

- 메모를 쓰는 사람으로서, 목록의 메모 텍스트를 더블클릭해 그 자리에서 내용을 고칠 수 있다.
- 메모를 고치는 사람으로서, Enter로 저장하고 Esc로 취소할 수 있고, 입력창 밖을 클릭해도 입력한 내용이 저장되어 잃어버리지 않는다.
- 메모를 고치는 사람으로서, 내용을 모두 지우고 저장해도 메모가 사라지지 않고 원래 내용이 유지된다.
- 메모를 고치는 사람으로서, 수정해도 메모가 목록의 같은 자리에 그대로 있다.
- 태그를 쓰는 사람으로서, 본문의 `#태그`를 고치면 메모 아래의 태그 칩도 그에 맞게 바뀐다.
- 여러 메모를 다루는 사람으로서, 한 번에 한 메모만 편집되고, 다른 메모를 더블클릭하면 편집 중이던 메모가 저장된 뒤 새 편집이 시작된다.

## 기술 결정

### 상황

수정 기능을 넣으려면 "어느 메모를 편집 중인지"와 편집 화면(입력창)을 어디에 둘지 정해야 한다. 현재 `App.tsx`(116줄)가 `memos`, 입력 텍스트, 선택 태그 등 모든 상태와 목록 렌더링을 갖고 있고, `src/components/`의 컴포넌트는 props로 데이터를 받는 표시 위주 구조다. 파일은 200줄을 넘기지 않는 규칙이 있다.

### 다른 후보

| 기준 | 안 1. `App.tsx`에 직접 | 안 2. `MemoItem` 컴포넌트 신설 + 편집 상태는 `App` (채택) | 안 3. `MemoItem` 신설 + 편집 상태는 `MemoItem` 안 |
|---|---|---|---|
| 구조 | `editingId` 상태와 입력창 JSX를 `App`의 목록 렌더링 안에 추가 | 메모 한 줄을 `MemoItem`으로 분리. `App`이 `editingId`, `handleSaveEdit`를 갖고 props로 내려줌 | `MemoItem`이 `isEditing`, 입력값을 자체 `useState`로 갖고 `onSave(id, text)`만 호출 |
| 고쳐야 할 곳 | `App.tsx`만 | `App.tsx` + 새 `MemoItem.tsx` | 안 2와 같음 |
| "한 번에 하나만" | `editingId` 하나로 자연스럽게 보장 | 안 1과 같음 | 상태가 메모마다 따로라, 다른 메모 더블클릭 시 이전 입력창의 blur 저장에 의존 |
| 기존 규칙과의 맞음 | `App`이 비대해짐(약 150줄 예상) | 높음. 상태는 `App`, 컴포넌트는 표시 중심 | 낮음. 컴포넌트가 상태를 가짐 |
| 테스트 쉬움 | 통합 테스트만 가능 | `MemoItem`을 props만으로 단위 테스트 가능 | `MemoItem` 단독 테스트 가능하나 내부 상태 검증이 필요 |
| 복잡도 | 낮음 (단기) | 중간 | 중간 |

### 결정

안 2. 메모 한 줄을 `MemoItem` 컴포넌트(named export, `src/components/MemoItem.tsx`)로 분리하고, `App`이 `editingId` 상태와 저장 처리(`handleSaveEdit`)를 가진다. `MemoItem`은 편집 여부와 콜백을 props로 받아 표시한다.

규칙
- `editingId`는 하나뿐이다(`string | null`). 편집 중인 메모 id를 담는다.
- 저장은 `id`가 같은 메모의 `text`만 `trim()`한 값으로 바꾸고, 위치와 `createdAt`은 건드리지 않는다. `trim()` 결과가 비면 바꾸지 않는다.
- 편집 중인 메모에서는 태그 칩과 `삭제` 버튼을 그리지 않는다.
- localStorage 저장은 기존 `useEffect`가 `memos` 변경을 감지해 그대로 처리한다.

### 결과

장점
- "한 번에 하나만 편집"이 상태 하나로 자연스럽게 지켜진다.
- `App.tsx`가 비대해지지 않아 200줄 제한을 지키기 쉽고, "상태는 `App`, 컴포넌트는 표시 위주"라는 기존 구조와 맞는다.
- `MemoItem`을 props만으로 단위 테스트할 수 있다.

단점
- 새 파일(`MemoItem.tsx`)과 props가 늘어난다(편집 여부, 저장·취소 콜백 등).
- 목록 렌더링 코드를 `App.tsx`에서 `MemoItem`으로 옮기는 리팩터링이 함께 필요하다.
- 편집 시작을 더블클릭으로 하므로 눈에 잘 띄지 않고, 키보드만으로는 편집을 시작할 수 없다.

## 이번에 안 만들 것

- 수정 시각·수정 이력 표시
- 실행 취소(Undo)
- 키보드만으로 편집 시작 (`수정` 버튼, F2 등)
- 터치 기기용 편집 진입 (길게 누르기 등)
- 여러 줄 편집 (한 줄 입력창만 사용)
- 여러 메모 동시 편집
- 자동 저장 (입력 중 실시간 저장)

## 용어 정의

- **편집 모드**: 메모 텍스트가 한 줄 입력창으로 바뀌어 내용을 고칠 수 있는 상태. 메모 텍스트를 더블클릭하면 시작한다.
- **저장**: 편집 모드를 끝내면서 입력창의 내용(앞뒤 공백 제거)으로 메모의 `text`를 바꾸는 것. Enter, 입력창 밖 클릭, 다른 메모의 더블클릭으로 일어난다.
- **취소**: 편집 모드를 끝내면서 메모를 원래 내용 그대로 두는 것. Esc로 일어난다. 빈 값 저장 시도도 같은 결과가 된다.
- **`editingId`**: 지금 편집 중인 메모의 id. 편집 중인 메모가 없으면 `null`.
