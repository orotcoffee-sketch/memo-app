# 메모 인라인 수정 기능 확정 스펙

인터뷰(7문항)에서 확정한 내용이다. 각 결정의 "왜"는 선택 당시 제시된 장단점을 바탕으로 정리한 것이다.

## 결정 사항

### 1. 편집 진입: 메모 텍스트를 더블클릭

- 왜: 사용자가 직접 선택했다. 버튼을 늘리지 않고 텍스트에서 바로 편집을 시작할 수 있어서.
- 감수할 점: 눈에 잘 띄지 않고, 키보드만으로는 편집을 시작할 수 없다.

### 2. 저장·취소: Enter 저장, Esc 취소, 입력창 밖 클릭은 저장

- 왜: 버튼 없이 쓰는 인라인 편집의 일반적인 방식이다. 바깥 클릭을 취소가 아니라 저장으로 해야 입력하던 내용이 사라지지 않는다.

### 3. 빈 값 저장: 저장하지 않고 원래 내용을 유지한 채 편집을 끝낸다

- 왜: 새 메모 추가 때 빈 값을 무시하는 규칙(`trim()` 후 비면 무시)과 같고, 실수로 다 지워서 메모가 사라지는 일을 막는다.

### 4. 위치·`createdAt`: 그대로 두고 `text`만 바꾼다

- 왜: 수정했다고 메모가 위로 올라가 순서가 바뀌면 혼란스럽고, `createdAt`은 만든 시각이다. `id`가 같은 메모의 `text`만 교체하면 된다.
- 태그는 본문에서 매번 파싱하므로 수정한 본문의 칩은 자동으로 바뀐다. 필터 중 선택 태그의 메모가 없어지면 기존 자동 해제 로직이 처리한다.

### 5. 동시 편집: 한 번에 하나만

- 왜: 편집 중에 다른 메모를 더블클릭하면 "바깥 클릭은 저장" 규칙에 따라 기존 편집이 저장되고 새 편집이 시작된다. 상태가 "편집 중인 메모 id" 하나면 된다.

### 6. 편집 중 표시: 텍스트 자리에 한 줄 입력창(현재 내용 채움, 자동 포커스), 그 메모의 태그 칩과 `삭제` 버튼은 숨김

- 왜: 새 메모 입력창과 같은 한 줄 입력이라 일관되다. 칩은 저장 전 옛 본문 기준이라 혼란스럽고, 편집 중 `삭제`는 바깥 클릭 저장과 겹쳐 동작이 모호하다.

### 7. 공백: 저장할 때 앞뒤 공백을 `trim()`

- 왜: 새 메모 추가와 같은 규칙이라, 수정한 메모만 공백이 남는 어긋남을 막는다.

## 용어 정의

- **편집 모드**: 메모 텍스트가 한 줄 입력창으로 바뀌어 내용을 고칠 수 있는 상태. 메모 텍스트를 더블클릭하면 시작한다.
- **저장**: 편집 모드를 끝내면서 입력창의 내용(앞뒤 공백 제거)으로 메모의 `text`를 바꾸는 것. Enter, 입력창 밖 클릭, 다른 메모의 더블클릭으로 일어난다.
- **취소**: 편집 모드를 끝내면서 메모를 원래 내용 그대로 두는 것. Esc로 일어난다. 빈 값 저장 시도도 같은 결과가 된다.
