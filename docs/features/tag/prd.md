# 태그 기능 PRD

근거 문서: [spec-fixed.md](./spec-fixed.md)

## 개요

메모 본문에 `#태그`를 쓰면 메모 아래에 태그 칩으로 보여 주고, 칩을 눌러 해당 태그의 메모만 모아 볼 수 있게 한다. 필터가 켜져 있는 동안 `MemoCount`는 필터 결과 개수를 보여 준다.

## 사용자 이야기

- 메모를 쓰는 사람으로서, 본문에 `#업무`처럼 쓰기만 하면 태그가 붙어서 별도 입력 없이 메모를 분류할 수 있다.
- 메모를 보는 사람으로서, 각 메모 아래의 태그 칩으로 어떤 태그가 달렸는지 한눈에 볼 수 있다.
- 메모를 찾는 사람으로서, 태그 칩을 눌러 같은 태그의 메모만 모아 볼 수 있고, 같은 칩을 다시 눌러 전체 목록으로 돌아올 수 있다.
- 필터를 쓰는 사람으로서, 상단 개수가 지금 보이는 목록의 메모 수와 일치하는 것을 볼 수 있다.

## 기술 결정

### 상황

메모 본문의 `#태그`를 칩으로 보여 주고 필터에 쓰려면 태그를 어딘가에서 얻어야 한다. 현재 `Memo`는 `{ id, text, createdAt }`이고 localStorage의 `memos` 키에 저장되어 있으며, 이미 저장된 메모가 있을 수 있다.

### 다른 후보

저장 방식 세 가지를 비교했다. 안 1이 채택안이다.

| 기준 | 안 1. 저장 없이 매번 파싱 | 안 2. `Memo`에 `tags: string[]` 필드 추가 | 안 3. 별도 localStorage 키에 태그 인덱스 저장 |
|---|---|---|---|
| 데이터 구조 | 변경 없음. `Memo`는 `{ id, text, createdAt }` 그대로이고 `text`에서 `#태그`를 추출 | `Memo`가 `{ id, text, createdAt, tags }`가 되고 추가 시점에 추출해 저장 | `memos`는 그대로 두고 `tags` 키에 `{ [memoId]: string[] }`를 따로 저장 |
| 고쳐야 할 곳 | 파싱 함수 신설, `App.tsx`의 목록 렌더링과 필터 상태, 칩 컴포넌트 | 위와 같음 + `Memo` 타입, `addMemo`, `loadMemos`(기존 메모에 `tags`가 없을 때 `[]`로 보정) | 안 2의 변경 + `tags` 키의 로드/저장 `useEffect`, `deleteMemo`에서 인덱스 정리 |
| 기존 코드와 비슷한 정도 | 높음. 저장 구조·`localStorage` 로직을 건드리지 않음 | 중간. 저장 방식은 같지만 기존 데이터를 보정해야 함 | 낮음. 상태와 저장 키가 하나 더 생김 |
| 테스트 쉬움 | 쉬움. 순수 함수 하나만 단위 테스트하면 됨 | 보통. 파싱 테스트에 더해 저장·불러오기·기존 데이터 보정 테스트가 필요 | 어려움. 두 저장소의 동기화와 삭제 시 정리까지 테스트해야 함 |
| 복잡도 | 낮음 | 중간 | 높음 |

### 결정

안 1. 태그를 저장하지 않고, 렌더링할 때마다 `text`에서 `#태그`를 추출한다. 추출은 순수 함수 하나로 분리한다.

파싱 규칙
- `#` 뒤의 한글·영문·숫자·`_`가 이어지는 부분까지를 태그로 본다. 그 밖의 문자(공백, 구두점, `-` 등)에서 태그가 끝난다. (예: `#a-b` → `#a`)
- 대소문자는 구분하지 않고(`#Work` = `#work`), 한 메모 안의 중복 태그는 하나로 합친다. 필터도 같은 기준으로 비교한다.

### 결과

장점
- `Memo` 타입과 localStorage 데이터가 그대로라 기존 메모 마이그레이션이 필요 없다.
- 고칠 곳이 파싱 함수, 칩 컴포넌트, `App.tsx`의 필터 상태와 목록 렌더링 정도로 적다.
- 본문과 태그가 따로 저장되지 않아 서로 어긋날 일이 없다.
- 파싱이 순수 함수라 단위 테스트가 쉽다.

단점
- 렌더링마다 파싱하므로 메모가 매우 많아지면 비용이 생긴다. 필요하면 `useMemo`로 완화할 수 있다.
- 태그가 별도 데이터가 아니라서, 태그에 색상 같은 부가 정보를 붙이려면 저장 구조를 새로 정해야 한다.
- 태그 이름을 바꾸려면 각 메모 본문을 고쳐야 한다.
- "무엇이 태그인가"가 파싱 규칙에 달려 있어, 한글·숫자·특수문자·중복 태그 처리 규칙을 구현 전에 정해야 한다.

## 이번에 안 만들 것

- 태그 색상
- 태그 이름 수정
- 자동 완성
- 태그 여러 개 동시 필터

## 용어 정의

- **태그**: 메모 본문 안에서 `#`로 시작하는 단어(예: `#업무`).
- **태그 칩**: 메모 본문 아래에 표시되는, 태그 하나를 나타내는 작은 버튼형 요소. 클릭하면 필터가 켜진다.
- **필터**: 선택한 태그가 달린 메모만 목록에 보이게 하는 상태. 같은 칩을 다시 누르면 해제된다.
- **필터 결과 개수**: 필터가 적용된 뒤 목록에 보이는 메모의 수. 필터가 없으면 전체 메모 수와 같다.
