# 태그 기능 확정 스펙

인터뷰(5문항)에서 확정한 내용이다. 각 결정의 "왜"는 선택 당시 제시된 장단점을 바탕으로 정리한 것이다.

## 결정 사항

### 1. 태그 입력: 메모 본문에 `#태그`로 작성

- 왜: 입력창을 새로 만들지 않고 기존 메모 입력 흐름 그대로 태그를 붙일 수 있어서.

### 2. 저장 방식: 저장하지 않고 렌더링할 때마다 본문에서 파싱

- 왜: `Memo` 타입과 localStorage의 `memos` 데이터를 바꾸지 않아 기존 메모에 대한 마이그레이션이 필요 없어서.

### 3. 표시: 본문 아래에 태그 칩으로 표시

- 왜: 본문 텍스트는 그대로 두고 태그만 따로 한눈에 볼 수 있게 하려고.

### 4. 필터: 태그 칩을 클릭하면 해당 태그의 메모만 표시 (다시 클릭하면 해제)

- 왜: 별도 검색 UI 없이 화면에 보이는 칩을 바로 눌러 메모를 좁힐 수 있어서.

### 5. 메모 개수: 필터가 켜진 동안 `MemoCount`는 필터 결과 개수를 표시

- 왜: 지금 화면에 보이는 목록과 숫자가 일치하고, `MemoCount`는 `count`만 바꿔 넘기면 되므로 수정이 필요 없어서.

## 용어 정의

- **태그**: 메모 본문 안에서 `#`로 시작하는 단어(예: `#업무`). 별도로 저장하지 않고 본문에서 그때그때 추출한다.
- **태그 칩**: 메모 본문 아래에 표시되는, 추출된 태그 하나를 나타내는 작은 버튼형 요소. 인터뷰에서는 "뱃지"라고 불렀다. 클릭하면 필터가 켜진다.
- **필터**: 선택한 태그가 달린 메모만 목록에 보이게 하는 상태. 같은 칩을 다시 누르면 해제되어 전체 목록으로 돌아간다.
- **필터 결과 개수**: 필터가 적용된 뒤 목록에 보이는 메모의 수. 필터가 없을 때는 전체 메모 수와 같다.
